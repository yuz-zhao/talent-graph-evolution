# GNN 模型定位与上线门控 v1.0

## 当前结论

当前模型是异构 GraphSAGE 无监督图表示预训练，训练目标为类型边重构。它生成 24 维节点辅助嵌入，用于影子观测和后续实验，不是监督式人才—岗位链接预测器。

因此，训练损失下降只能证明优化过程能够拟合当前图结构，不能证明人才—岗位匹配准确率、排序质量或业务转化率有所提升。

## 本次优化

1. GNN 从生产融合的固定 5% 权重改为 `shadow_only`，生产权重为 0，不影响召回、排序和最终匹配分。
2. API 同时输出 `productionWeight=0`、`affectsRanking=false`、`supervisedRanker=false` 和 `formalMatchingAccuracyEligible=false`。
3. 用户端改为“GNN辅助表征（影子）”，明确该数值不是匹配准确率。
4. 管理端算法权重同步为 0，并写明无监督边重构的能力边界。
5. 增加自动验收，若 GNN 再被放回融合权重或被标成监督匹配器，校验直接失败。

## 当前数据门控

- 图中人才画像：120 个。
- 数据集内人才—岗位交互标签：0 条。
- 非演示行为：3 条。
- 强结果标签（申请、面试、录用）：0 条。
- 监督模型最低启动门槛：300 个真实人才画像、3000 条非合成交互，并包含可审计的强结果边。

当前数据不满足监督训练和独立有效性评价条件，所以不应训练或发布“监督式 GNN 匹配器”。

## 未来进入生产的验收顺序

1. 收集经授权、去标识化的真实人才画像以及曝光、点击、收藏、申请、面试、录用事件。
2. 以时间切分建立训练、验证和完全独立测试集，避免同一人才或同一岗位泄漏。
3. 训练监督式人才—岗位链接预测头；无监督 GraphSAGE 只作为初始化或特征来源。
4. 与不含 GNN 的生产基线比较 Recall@K、NDCG@K、MRR、AUC/PR-AUC，并报告置信区间。
5. 只有独立测试和消融实验均证明稳定增益，且公平性、冷启动和漂移检查通过，才允许赋予非零生产权重。

## 对外表述

可以表述为：

> 已完成异构 GraphSAGE 的无监督图表示预训练，可生成辅助节点嵌入；当前以影子模式运行，不参与生产匹配排序。由于尚缺真实人才—岗位结果边，暂不声明监督匹配准确率。

不能表述为：“GNN 核心匹配模型已训练完成”或“GNN 匹配准确率已经验证”。
